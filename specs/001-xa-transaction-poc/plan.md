# Implementation Plan: XA Transaction POC — Reliable Message Production & Consumption

**Branch**: `001-xa-transaction-poc` | **Date**: 2026-04-28 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/001-xa-transaction-poc/spec.md`

## Summary

Validate that a Spring Boot 3.5 / Java 25 application can produce events atomically to MySQL
and Apache Artemis within a single XA/JTA distributed transaction. Key correctness invariant:
when the producer transaction rolls back (fault injected after JMS send, before DB commit),
the consumer MUST receive no message. Secondary goal: measure committed-transaction throughput
(≥500 msgs/sec) and p95 latency (≤200ms) under sustained load.

## Key Implementation Notes

### Atomikos Auto-Configuration

The `transactions-spring-boot3-starter` auto-registers `XADataSourceWrapper` and
`XAConnectionFactoryWrapper`. Declare `MysqlXADataSource` and `ActiveMQXAConnectionFactory`
as `@Bean`s — the starter's wrappers pick them up and expose pooled, JTA-enrolled
`DataSource` and `ConnectionFactory` beans that Spring Boot's JDBC/JMS auto-configuration
uses transparently.

No manual `UserTransactionManager`, `UserTransaction`, or `JtaTransactionManager` bean
declarations are needed — the Atomikos starter handles all of that.

### XA-Critical MySQL Flags

The JDBC URL passed to `MysqlXADataSource` MUST include:
- `allowXAStatements=true` — enables the driver to issue XA commands
- `pinGlobalTxToPhysicalConnection=true` — prevents XA session confusion under connection reuse

### Testcontainers + XA Datasource

`@ServiceConnection` does not work for XA datasources since the XA beans are manually
configured. Use `@DynamicPropertySource` on the abstract base test class to inject container
URLs into `spring.datasource.url` and `spring.artemis.broker-url`.

The Atomikos log directory MUST be set to a `@TempDir` per-test-JVM via `@DynamicPropertySource`
to prevent log corruption across test runs.

### Fault Injection Placement

The fault is thrown AFTER `jmsTemplate.send(...)` and BEFORE the `@Transactional` method
returns. This positions the exception inside the XA transaction boundary, triggering Atomikos
to issue `XA ROLLBACK` to both MySQL and Artemis. The consumer should receive nothing.

### Consumer Test Isolation

`EventConsumerService.getReceivedMessages()` returns a `CopyOnWriteArrayList`. Each integration
test MUST call `eventConsumerService.clearMessages()` in `@BeforeEach` to prevent message
bleed-through from previous tests (especially if `AbstractIntegrationTest` reuses the Spring
context).
